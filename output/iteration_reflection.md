# 迭代反思（至少 2 轮）

## 第一轮
- 我观察到的关键问题：AI 初版很容易直接给出“系数显著”的结论，但缺少识别目标、缺少边界声明，也缺少主题适配的机制解读。
- 我做的修订：先写识别目标（estimand），明确处理组/对照组、识别假设、主要威胁；在各项 prompt 中加入边界与验证要求；要求汇总表写出“结论/观察/判断”。
- 证据：第一轮更像“结果输出”，第二轮更像“研究设计与审计”。

## 第二轮
- 我观察到的关键问题：初版 Skill 太依赖具体变量名（digital、log_tfp、firm_id），不适合迁移到其他主题。
- 我做的修订：把 Skill 改为先读取数据说明/README，识别 y、D、id、t 和控制变量；增加工作步骤、检查清单、验证方式与迁移说明。
- 证据：同一套结构可以迁移到最低工资/就业、医保/健康等主题，而无需重写核心逻辑。

## 一般适用性论证
- 需要改的地方：结果变量 y、处理变量 D、个体维度 id、时间维度 t、固定效应与聚类层级。
- 不需要改的地方：DID 的基本逻辑、稳健性检验顺序、Skill 的六模块结构、Agent 的评估框架。
- 结论：这套设计是“可迁移的制度”，而不是为本项目定制的硬编码脚本。
